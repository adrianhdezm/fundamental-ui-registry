# Porting tracker: React registry

This folder tracks the port of the components to React: which sources each one comes from, how its stories compare
with them, and how it looks next to fundamental-styles. [`components/`](components/) has one report per component.

## Sources

- **[fundamental-react](https://github.com/SAP/fundamental-react)** (`SAP/fundamental-react` `main` at
  [`490bd2f`](https://github.com/SAP/fundamental-react/tree/490bd2fca46e0fb09e48e488c9d7c030a166c6bf), May 2026):
  React 17, Storybook 6, fundamental-styles 0.26. Its 41 component folders other than Table map to 45 registry
  components (Button also gives segmented-button; Forms gives form, input, checkbox and radio). Its stories are an
  input; its code is not copied (class names, Popper, Moment and prop-types are gone).
- **The Angular package** ([`packages/angular`](../../../angular/)): the API, behaviour, ARIA, keyboard handling and
  Tailwind classes of every component, themselves ported from `@fundamental-ngx/core`. Nothing is imported from it:
  code is rewritten in React with Base UI.
- **[fundamental-styles](https://sap.github.io/fundamental-styles/)**: the visual reference.

## Phases

1. **Phase 1:** the 45 components with a fundamental-react source, in dependency order (icon and button first).
2. **Phase 2:** the other Angular components, which have no fundamental-react source, ported from the Angular package.

That gives 94: Angular's 92 plus counter and search-input, which have no Angular equivalent. Table is out of scope.

## When a component is done

- Stories cover every example of the fundamental-react stories and of the Angular stories (minus n/a ones, such as
  fundamental-react's `cssNamespace` "no styles" stories), with "Open: …" stories for overlays.
- The spec covers the behaviours of the Angular spec and of the fundamental-react tests, in Vitest browser mode.
- `pnpm check` passes: typecheck, styles, registry, tests, and axe on every story in Horizon and Horizon HC Black.
- **Visual:** `pnpm visual <name>` compares chosen elements with the matching fundamental-styles stories in all 16
  combinations of theme (Horizon, Dark, HC Black, HC White), density (cozy, compact) and direction (LTR, RTL), by
  computed style and by pixels with a 3% tolerance. Cozy and compact in Horizon, LTR and RTL, are also reviewed by
  eye in Storybook. Every difference is fixed, or kept with the reason when the Fiori guidelines say fundamental-styles
  is wrong, and logged in the component's report. Combinations fundamental-styles cannot render are checked against
  the SAP tokens and marked so.
- The report in `components/<name>.md` is written and `tracker.json` says `done` with the visual result.

## Angular issues found while porting

Visual differences found in the Angular package while porting; Angular changes are out of scope for this work, so
they are listed here for a follow-up pull request.

| Component      | Issue                                                                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| icon           | The icon box is taller than fundamental-styles' (35px instead of 32px at `md`): `tailwind-merge` drops `leading-none` because the size class (`text-[2rem]`) comes after it. Fixed in React by moving it after.                                   |
| icon           | Narrow glyphs get a box as wide as the glyph instead of 1em, so e.g. the menu arrow of an icon-only menu button is 10px wide and the button 6px narrower than fundamental-styles'. Fixed in React with `w-[1em]`.                                 |
| link           | No `text-underline-offset`: the underline sits 2px higher than fundamental-styles' (0.125rem), visible on subtle links and in the high-contrast themes. Fixed in React with `underline-offset-[0.125rem]`.                                        |
| busy-indicator | The dots use `--sapContent_BusyColor` (`#0064d9` in Horizon, `#4db1ff` in Horizon Dark); fundamental-styles uses `--fdBusy_Indicator_Dot_Color`, `#0070f2` in both (the busy colour in HC). Fixed in React with the variable in `extensions.css`. |
| layout-grid    | The grid sets no typography, so column text takes the page font instead of fundamental-styles' SAP font, size and colour.                                                                                                                         |
| checkbox       | The label text inherits the label colour (`--sapContent_LabelColor`) and a 1rem line height; fundamental-styles uses `--sapTextColor` with a normal line height, so the text is lighter.                                                          |
| checkbox       | In the HC themes, hovered success, warning and information checkboxes get `--sapSelectedColor` instead of `--sapField_Hover_Background`.                                                                                                          |
| checkbox       | The display-only box loses `leading-[normal]` to `tailwind-merge` (it comes before `text-[1rem]`); computed styles only, not visible.                                                                                                             |
| input          | Compact textareas stay one line high (26px): `textareaBase` sets `h-auto` but not `compact:h-auto`, so the compact field height wins whatever the rows.                                                                                           |
| layout-panel   | The title uses `font-bold` on the 72-Bold header font, so the browser adds synthetic bold; fundamental-styles has `font-weight: normal`.                                                                                                          |
| layout-panel   | In a narrow panel the head shrinks to a few pixels and the title runs under the actions (seen in the React port with the same classes, not checked in Angular itself).                                                                            |
| popover        | The resize handle has an empty `data-glyph`, so no glyph shows.                                                                                                                                                                                   |
| popover        | The resize handle is always at the bottom-end (top-end when above) corner, even for left/right placements and end alignments; fundamental-styles puts it in the corner away from the trigger.                                                     |
| radio          | The radio label text inherits `--sapField_TextColor` and `leading-4`; fundamental-styles uses `--sapTextColor` with a normal line height (#f5f6f7, not #fff, in Horizon Dark).                                                                    |
| radio          | In the HC themes, hovered success, warning and information radios take `--sapSelectedColor` instead of `--sapField_Hover_Background` (as checkbox).                                                                                               |
| radio          | The read-only label has `cursor-default`; fundamental-styles keeps `pointer`.                                                                                                                                                                     |
| switch         | Hover colours never apply: `group-hover/sw:` sits on the element that is itself `group/sw`, and the variant only matches descendants.                                                                                                             |
| switch         | The on/off texts and icons lose their line height to `tailwind-merge` (a `leading-*` before a `text-*` size); computed styles only.                                                                                                               |
| switch         | A semantic switch without `ariaLabelledBy` is named only "Accept" or "Decline", and `ariaLabel` goes on the `<label>` instead of the input.                                                                                                       |
| info-label     | `align-middle` (not in fundamental-styles) moves inline labels 0.3px down.                                                                                                                                                                        |
| avatar         | With `border` plus `transparent`, `tile` or `placeholder` the border disappears and the hover border is wrong (tailwind-merge keeps the later `--av-border`).                                                                                     |
| avatar         | A loaded image keeps the accent background and border colour around it; fundamental-styles uses `--sapAvatar_Lite_Background` and `--sapAvatar_Lite_BorderColor`.                                                                                 |
| avatar         | Value state badges use the state border tokens instead of the state text colours (e.g. `#e90b0b` instead of `#aa0808`).                                                                                                                           |
| avatar         | `rounded-full` computes to 3.35544e+07px instead of 100%, and the badge loses its 1 line height; computed styles only.                                                                                                                            |
| list           | List icons and the unread dot lose `leading-none` to tailwind-merge (20px/7px high instead of 18px/6px).                                                                                                                                          |
| list           | Thumbnail icons stay 1rem instead of 2rem.                                                                                                                                                                                                        |
| list           | A hovered link keeps a transparent bottom border; fundamental-styles uses the list border colour.                                                                                                                                                 |
| object-status  | `min-w-6` makes icon-only statuses 24px wide instead of 16px (inverted 24px instead of 22px) and centres short texts.                                                                                                                             |
| object-status  | Large inverted statuses use 72-Semibold; fundamental-styles uses the regular 72 (6px narrower).                                                                                                                                                   |
| object-status  | `hcFocus()` builds its `hc:focus:` classes at runtime, so Tailwind never generates them and focused clickable statuses lose their colour in HC.                                                                                                   |
| object-status  | The root line height is dropped by tailwind-merge (`leading-(--os-h)` before the font size); computed styles only.                                                                                                                                |
| tree           | `wrapContent` items get `py-1`, so wrapping rows are 8px taller than fundamental-styles'.                                                                                                                                                         |
| tree           | Tree item buttons get a 2px start margin; fundamental-styles' resolves to 0.                                                                                                                                                                      |
| tree           | The "No data" row is 1px too low (44px instead of 45px): its text has a normal line height.                                                                                                                                                       |
| tree           | The expander lacks the button corner radius (visible only with a focus outline).                                                                                                                                                                  |
